    41→## Overview
    42→
    43→**OWL-DNS-Synergy** is a unified dual-channel resilient access engine that merges 7 independent
    44→repositories into a single coordinated stack. It combines HTTP proxy evasion via OWL-AGENT v4.2
    45→with DNS tunneling via LLM-DNS-Proxy, and integrates 5 auxiliary components for SOCKS pooling,
    46→MITM stealth, CONNECT chaining, OAuth harvesting, and Rust-based stealth proxying.
    47→
    48→The stack implements a **5-layer architecture**:
    49→
    50→| Layer | Name             | Responsibility                                           |
    51→|-------|------------------|----------------------------------------------------------|
    52→| L1    | DNS Chunking     | Base36 encoding, 63-byte DNS labels, 253-byte qname     |
    53→| L2    | Crypto           | Fernet AES-128-CBC encryption, zlib compression, budget |
    54→| L3    | OWL Core         | HTTPCache, RequestDedup, QualityScorer, RateLimiter, CB  |
    55→| L4    | SmartChannelRouter v3 | 7-channel cascade, EMA learning, flood protection  |
    56→| L5    | AutoClaw         | OAuth harvesting, token rotation, OpenAI-compatible proxy|
    57→
    58→Requests flow through the SmartChannelRouter which selects the optimal channel from a
    59→7-channel cascade with automatic failover. The router tracks per-domain preferences using
    60→exponential moving average (EMA) learning and protects against DNS flooding with token-bucket
    61→rate limiting. Each channel is guarded by an independent 3-state Circuit Breaker.

   119→### Channel Cascade Order
   120→
   121→The SmartChannelRouter v3 attempts channels in priority order with automatic failover:
   122→
   123→```
   124→1. cached         -- Check HTTP cache (L3) for fresh response
   125→2. http_proxy     -- OWL-AGENT proxy with quality scoring
   126→3. socks_pool     -- prox5 SOCKS5 pool with validation
   127→4. dns_tunnel     -- LLM-DNS-Proxy encrypted DNS channel
   128→5. mitm_stealth   -- secret-agent MITM with TLS fingerprints
   129→6. connect_chain  -- proxytunnel CONNECT chaining
   130→7. http_direct    -- Direct HTTP request (last resort)
   131→```
   132→
   133→Each channel is independently guarded by a 3-state Circuit Breaker (CLOSED, OPEN, HALF_OPEN).
   134→When a channel's circuit opens, the router automatically falls through to the next channel
   135→in the cascade.
   136→
   137→### Layer Responsibilities
   138→
   139→| Layer | Component            | Key Classes / Functions                           |
   140→|-------|----------------------|---------------------------------------------------|
   141→| L1    | DNS Chunking         | `DNSChunker`, `base36encode()`, `bytes_to_base36()` |
   142→| L2    | Crypto               | `CryptoManager`, Fernet encrypt/decrypt, zlib     |
   143→| L3    | OWL Core             | `HTTPCache`, `RequestDeduplicator`, `QualityScorer`, `AdaptiveRateLimiter`, `CircuitBreaker` |
   144→| L4    | SmartChannelRouter   | `SmartChannelRouterV3`, `ChannelCircuitBreaker`, `DNSFloodProtector`, `EMAPreferenceTracker` |
   145→| L5    | AutoClaw             | OAuth harvesting, `AutoClawProxy`, token rotation, OpenAI-compatible API |

   149→## Features
   150→
   151→### Core Engine
   152→
   153→- **Smart Channel Router v3** with 7-channel cascade and automatic failover
   154→  - Priority-ordered channel selection: cached, http_proxy, socks_pool, dns_tunnel, mitm_stealth, connect_chain, http_direct
   155→  - Per-channel 3-state Circuit Breaker (CLOSED, OPEN, HALF_OPEN)
   156→  - EMA (Exponential Moving Average) domain preference learning
   157→  - DNS flood protection with token bucket + per-client rate limiting
   158→
   159→### DNS Tunneling
   160→
   161→- **Fernet AES-128-CBC encryption** for all tunneled data
   162→- **Base36 chunking** with DNS-safe encoding (63-byte labels, 253-byte qname)
   163→- **Zlib compression** with 100 MB global decompression budget (Memory Fix M-C1)
   164→- Session-based chunk reassembly with TTL-based eviction (Memory Fix M-D1)
   165→- Maximum pending sessions cap (Memory Fix M-D3)
   166→
   167→### Resilience
   168→
   169→- **3-state Circuit Breaker** (CLOSED -> OPEN -> HALF_OPEN) per channel
   170→  - Configurable failure threshold (default: 5)
   171→  - Configurable recovery timeout (default: 30s)
   172→  - Configurable success threshold for HALF_OPEN -> CLOSED (default: 2)
   173→- **EMA domain preference learning** tracks per-domain channel success rates
   174→- **Adaptive rate limiting** adjusts per-domain rate based on response codes (429/503)
   175→
   176→### Memory Safety
   177→
   178→- **DNS flood protection** with token bucket + per-client rate limit (10 qps per client)
   179→- **Quality scoring** with `MAX_TARGETS` cap (5000) to prevent unbounded growth
   180→- **HTTP cache** with LRU eviction + max entry size (50 KB) rejection
   181→- **Request deduplication** to prevent duplicate concurrent in-flight requests
   182→- **Decompression budget** (100 MB concurrent) to prevent zlib bomb attacks
   183→- **DNS session cap** (10,000 max pending) with TTL eviction
   184→
   185→### Production
   186→
   187→- **Token encryption at rest** using Fernet (AES-128-CBC) via `AUTOCLAW_TOKEN_KEY`
   188→- **Gunicorn** production server with eventlet workers
   189→- **Prometheus metrics** (12+ gauges/counters/histograms) for full observability
   190→- **Systemd** deployment with security hardening (MemoryMax, NoNewPrivileges, ProtectSystem=strict)
   191→- **Structured logging** via Python logging module with configurable log levels
   192→- **AutoClaw** free LLM backend providing OpenAI-compatible proxy at `/v1/chat/completions`

   196→## Quick Start
   197→
   198→### Ubuntu / Debian
   199→
   200→```bash
   201→# Clone the repository
   202→git clone https://github.com/user/owl-dns-synergy.git
   203→cd owl-dns-synergy
   204→
   205→# Run the unified installer
   206→./install.sh
   207→```
   208→
   209→The installer will:
   210→1. Check system requirements (Python 3.10+, pip, git)
   211→2. Clone the LLM-DNS-Proxy submodule
   212→3. Create the directory structure at `~/.owl-dns-synergy/`
   213→4. Set up a Python virtual environment
   214→5. Install all Python dependencies
   215→6. Install the `owl-dns-synergy` package in editable mode
   216→7. Generate default configuration files
   217→8. Create a systemd service template
   218→
   219→### Basic Usage
   220→
   221→```bash
   222→# Generate an encryption key for DNS tunneling
   223→owl-dns-synergy generate-key
   224→# Output: LLM_PROXY_KEY=...
   225→
   226→# Set required environment variables
   227→export OPENAI_API_KEY="sk-..."
   228→export LLM_PROXY_KEY="<key from generate-key>"
   229→
   230→# Test connectivity on both channels
   231→owl-dns-synergy test-connection
   232→
   233→# Fetch a URL through the optimal channel
   234→owl-dns-synergy fetch https://example.com
   235→
   236→# Fetch with verbose output (shows channel + latency)
   237→owl-dns-synergy fetch https://example.com --verbose
   238→
   239→# Fetch using a specific channel
   240→owl-dns-synergy fetch https://example.com --channel dns
   241→
   242→# View channel statistics
   243→owl-dns-synergy stats
   244→
   245→# Start the DNS tunneling server
   246→owl-dns-synergy serve --host 127.0.0.1 --port 5353

   487→### DNS Tunneling Examples
   488→
   489→```python
   490→from owl_dns_synergy.core import CryptoManager, DNSChunker
   491→from owl_dns_synergy.config import SynergyConfig
   492→
   493→# Initialize components
   494→config = SynergyConfig()
   495→crypto = CryptoManager(config=config)
   496→chunker = DNSChunker(config=config)
   497→
   498→# Encrypt and chunk a message for DNS tunneling
   499→message = "Explain the theory of relativity"
   500→encrypted = crypto.encrypt(message)
   501→chunks = chunker.create_chunks(encrypted)
   502→
   503→for i, chunk in enumerate(chunks):
   504→    print(f"DNS query {i}: {chunk}")
   505→
   506→# Reassemble and decrypt
   507→session_id, data = chunker.process_chunk_query(chunks[0])
   508→# ... after all chunks received ...
   509→decrypted = crypto.decrypt(data)
   510→```

   531→print(response.choices[0].message.content)
   532→```

   749→## Security
   750→
   751→### Token Encryption at Rest
   752→
   753→All AutoClaw tokens are encrypted at rest using Fernet (AES-128-CBC) before being written
   754→to disk. The encryption key is provided via the `AUTOCLAW_TOKEN_KEY` environment variable.
   755→
   756→```bash
   757→# Generate a token encryption key
   758→export AUTOCLAW_TOKEN_KEY=$(python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())")
   759→```
   760→
   761→If `AUTOCLAW_TOKEN_KEY` is not set, the application will refuse to start in production mode.
   762→
   763→### Memory Limits
   764→
   765→Multiple layers of memory protection prevent resource exhaustion:
   766→
   767→| Protection              | Limit          | Implementation                           |
   768→|-------------------------|----------------|------------------------------------------|
   769→| Systemd MemoryMax       | 1 GB           | `MemoryMax=1G` in service unit           |
   770→| Systemd MemoryHigh      | 768 MB         | `MemoryHigh=768M` (throttle above this)  |
   771→| Decompression Budget    | 100 MB         | Global concurrent zlib output cap (M-C1) |
   772→| HTTP Cache Max Entry    | 50 KB          | Reject entries > 50 KB (M-O5)            |
   773→| HTTP Cache Max Count    | 1,000          | LRU eviction at capacity (M-O1)          |
   774→| DNS Sessions Max        | 10,000         | Reject new sessions above cap (M-D3)     |
   775→| Quality Targets Max     | 5,000          | Evict lowest-score target at cap         |
   776→
   777→### Systemd Security Hardening
   778→
   779→The service units apply the following systemd security directives:
   780→
   781→- **NoNewPrivileges=true** -- Prevents privilege escalation via setuid/setgid
   782→- **ProtectSystem=strict** -- Read-only `/usr`, `/boot`, `/etc`; no writes except `ReadWritePaths`
   783→- **ProtectHome=true** -- `/home`, `/root`, `/run/user` are inaccessible
   784→- **PrivateTmp=true** -- Isolated `/tmp` and `/var/tmp` namespaces
   785→- **CapabilityBoundingSet=CAP_NET_BIND_SERVICE** -- Only network binding capability allowed
   786→- **AmbientCapabilities=CAP_NET_BIND_SERVICE** -- Inherit binding capability for low-port binding
   787→- **ReadWritePaths** -- Only `/var/log/owl-dns-synergy` and `/var/cache/owl-dns-synergy` writable
   788→
   789→### API Key Authentication
   790→
   791→All AutoClaw proxy endpoints require API key authentication via the `Authorization: Bearer <key>`
   792→header. Keys are validated against the configured `OPENAI_API_KEY` and backup
   793→`OPENROUTER_KEY_N` keys.

   807→### DNS Flood Protection
   808→
   809→The DNS flood protector implements a two-layer defense:
   810→
   811→1. **Global token bucket** -- Rate limits total DNS queries across all clients
   812→   - Default: 50 queries/second, burst allowance of 100
   813→2. **Per-client rate limit** -- Tracks queries per client IP using a sliding window
   814→   - Default: 10 queries/second per client IP
   815→   - Client IPs tracked in a bounded dictionary

   818→
   819→## Architecture Layers (Detailed)
   820→
   821→### L1: DNS Chunking
   822→
   823→The DNS Chunking layer encodes binary data into DNS-safe query names for tunneling
   824→through DNS infrastructure that only allows standard query/response traffic.
   825→
   826→**Implementation details:**
   827→
   828→- **Base36 encoding** -- Binary data is converted to base36 (alphanumeric only) for DNS-safe
   829→  transport. The encoding uses `0-9a-z` characters with a length prefix separated by `_`.
   830→- **63-byte DNS labels** -- Each DNS label is limited to 63 bytes per RFC 1035. Data is split
   831→  into labels of at most 50 bytes each (`MAX_DATA_LABEL_LENGTH = 50`).
   832→- **253-byte qname limit** -- The total DNS query name (including all labels, dots, and the
   833→  suffix) must not exceed 253 bytes (`MAX_DNS_QNAME_LENGTH = 253`).
   834→- **Session-based reassembly** -- Each message is assigned an 8-hex-digit session ID. The
   835→  query format is: `m.<session_id>.<chunk_index>.<total_chunks>.<data_labels>.<dns_suffix>`
   836→- **TTL-based session eviction** (M-D1) -- Sessions older than `session_ttl` (default 60s)
   837→  are evicted on each incoming query to prevent unbounded memory growth.
   838→- **Max pending sessions cap** (M-D3) -- New sessions are rejected when `pending_messages`
   839→  reaches `max_pending_sessions` (default 10,000).
   840→
   841→**Key classes:** `DNSChunker`, `base36encode()`, `base36decode()`, `bytes_to_base36()`, `base36_to_bytes()`
   842→
   843→### L2: Crypto
   844→
   845→The Crypto layer provides encryption and compression for DNS tunneled data.
   846→
   847→**Implementation details:**
   848→
   849→- **Fernet AES-128-CBC** -- All data is encrypted using the `cryptography` library's Fernet
   850→  scheme, which provides authenticated encryption with AES-128-CBC and HMAC-SHA256.
   851→- **Zlib compression** -- Data is compressed with `zlib.compress(level=9)` before encryption
   852→  to minimize the number of DNS queries required.
   853→- **100 MB decompression budget** (M-C1) -- A global concurrent decompression budget of
   854→  100 MB prevents zip bomb attacks. Each decompression operation estimates the worst-case
   855→  expanded size (12x the compressed size for zlib) and checks against the budget. If the
   856→  budget is exceeded, a `MemoryError` is raised.
   857→- **Atomic disk writes** -- Cache files are written to a `.tmp` path first, then renamed
   858→  using `os.replace()` which is atomic on POSIX filesystems.
   859→- **Base64 binary safety** -- Cached content is stored as base64 to prevent encoding
   860→  corruption of binary data (Audit Fix: previously used `decode('utf-8', errors='replace')`
   861→  which corrupted binary content).
   862→
   863→**Key classes:** `CryptoManager`
   864→
   865→### L3: OWL Core
   866→
   867→The OWL Core layer provides the resilience primitives from OWL-AGENT v4.2.
   868→
   869→**HTTPCache:**
   870→- LRU eviction using `OrderedDict` for O(1) operations (M-O1)
   871→- Periodic cleanup every 60 seconds removing expired entries
   872→- Maximum entry size rejection (M-O5): entries larger than 50 KB are silently rejected
   873→- Disk persistence with atomic writes and base64 binary encoding
   874→- SHA-256 cache keys incorporating method, URL, params, and protocol
   875→
   876→**RequestDeduplicator:**
   877→- Prevents duplicate concurrent requests using `asyncio.Future` sharing
   878→- Lock-free await for joined requests (lock released before await to prevent deadlock)
   879→- Automatic cleanup of in-flight entries in `finally` block
   880→
   881→**QualityScorer:**
   882→- Exponential moving average scoring: `new = old * 0.9 + current * 0.1`
   883→- Tracks last 100 latency measurements per target
   884→- `MAX_TARGETS = 5000` cap with lowest-score eviction (M-O2)
   885→- `get_best()` for selecting highest-quality candidate
   886→
   887→**AdaptiveRateLimiter:**
   888→- Per-domain rate adjustment based on HTTP status codes
   889→- 429/503: rate *= 0.5 (halve rate)
   890→- 2xx: rate *= 1.1 (increase by 10%)
   891→- Bounds: `min_rate=0.1`, `max_rate=5.0` requests/second
   892→
   893→**CircuitBreaker (from circuitbreaker library):**
   894→- Failure threshold: 5 consecutive failures
   895→- Recovery timeout: 30 seconds
   896→- States: CLOSED (normal), OPEN (fail-fast), HALF_OPEN (probe)
   897→
   898→**Key classes:** `HTTPCache`, `RequestDeduplicator`, `QualityScorer`, `AdaptiveRateLimiter`, `TokenBucket`, `ProxyEntry`, `RedisStore`
   899→
   900→### L4: SmartChannelRouter v3
   901→
   902→The SmartChannelRouter v3 is the integration layer that coordinates all 7 channels.
   903→
   904→**7-channel cascade:**
   905→1. `cached` -- Check HTTP cache for fresh response
   906→2. `http_proxy` -- OWL-AGENT proxy with quality scoring and key rotation
   907→3. `socks_pool` -- prox5 Go SOCKS5 pool with validation engine
   908→4. `dns_tunnel` -- LLM-DNS-Proxy encrypted DNS channel
   909→5. `mitm_stealth` -- secret-agent MITM proxy with TLS fingerprints
   910→6. `connect_chain` -- proxytunnel CONNECT method chaining
   911→7. `http_direct` -- Direct HTTP request as last resort
   912→
   913→**Per-channel Circuit Breaker:**
   914→- 3-state implementation: `CLOSED -> OPEN -> HALF_OPEN -> CLOSED`
   915→- `CLOSED`: Normal operation, all requests pass
   916→- `OPEN`: Circuit tripped, all requests fail-fast, timer starts
   917→- `HALF_OPEN`: One probe request allowed; success -> CLOSED, failure -> OPEN
   918→- Configurable per channel: `failure_threshold`, `recovery_timeout`, `success_threshold`
   919→
   920→**EMA Domain Preference Learning:**
   921→- Per-domain exponential moving average of channel success rates
   922→- Automatically promotes the best-performing channel for each domain
   923→- Preference weights decay over time to adapt to changing conditions
   924→
   925→**DNS Flood Protection:**
   926→- Global token bucket: configurable QPS (default 50) with burst allowance (default 100)
   927→- Per-client rate limiting: 10 queries/second per client IP
   928→- Bounded client tracking dictionary to prevent memory growth
   929→- Blocked queries increment `synergy_dns_flood_blocked_total` counter
   930→
   931→**OpenRouter Key Rotation:**
   932→- Round-robin API key rotation with cooldown on errors
   933→- 429 (rate limit): 60-second cooldown
   934→- 401/403 (auth failure): 300-second cooldown
   935→- Other errors: 10-second cooldown
   936→- Automatic rotation to next available key on error
   937→
   938→**Key classes:** `SmartChannelRouterV3`, `ChannelCircuitBreaker`, `DNSFloodProtector`, `OpenRouterKeyRotator`, `EMAPreferenceTracker`
   939→
   940→### L5: AutoClaw
   941→
   942→The AutoClaw layer provides free LLM backend access through automated account management.
   943→
   944→**OAuth Harvesting:**
   945→- Automated login to free LLM providers (e.g., OpenRouter free tier)
   946→- Browser automation via secret-agent for CAPTCHA solving
   947→- Credential management from `accounts.txt`
   948→
   949→**Token Rotation:**
   950→- Harvested OAuth tokens are encrypted at rest with Fernet (`AUTOCLAW_TOKEN_KEY`)
   951→- Automatic token refresh before expiration
   952→- Round-robin distribution across available tokens
   953→
   954→**OpenAI-Compatible Proxy:**
   955→- Implements `/v1/chat/completions` and `/v1/models` endpoints
   956→- Request routing to the best available free backend
   957→- Rate limit detection and automatic backend rotation
   958→- Usage tracking via `/wallet` and `/ledger` endpoints
   959→
   960→**Production Server:**
   961→- Gunicorn with eventlet workers (4 workers default)
   962→- Memory limit: 512 MB (`MemoryMax=512M`)
   963→- Max requests per worker: 1000 with jitter for staggered restarts
   964→- 120-second request timeout
   965→
   966→**Key classes:** `AutoClawProxy`, token management in `auth` module

  1179→## Contributing
  1180→
  1181→Contributions to OWL-DNS-Synergy are welcome. Please follow these guidelines:
  1182→
  1183→### Getting Started
  1184→
  1185→1. Fork the repository
  1186→2. Create a feature branch: `git checkout -b feature/my-feature`
  1187→3. Make your changes with tests
  1188→4. Ensure all tests pass: `pytest`
  1189→5. Run the memory fix tests: `python scripts/test-memory-fixes.py`
  1190→6. Run the E2E tests: `python scripts/test-e2e-pipeline.py`
  1191→7. Submit a pull request
  1192→
  1193→### Code Style
  1194→
  1195→- Follow PEP 8 with 120-character line limit
  1196→- Use type hints on all public function signatures
  1197→- Use `dataclass(slots=True)` for performance-critical data structures
  1198→- Use `asyncio.Lock` for async contexts, `threading.Lock` for sync contexts
  1199→- Log using the structured logging pattern: `logger = logging.getLogger("owl-dns-synergy.<module>")`
  1200→
  1201→### Memory Safety
  1202→
  1203→All new code must respect the memory budget constraints:
  1204→
  1205→- HTTP cache entries must not exceed `max_entry_bytes` (50 KB)
  1206→- DNS sessions must respect `max_pending_sessions` (10,000)
  1207→- Quality scorer must respect `MAX_TARGETS` (5,000)
  1208→- Decompression operations must check the global budget (100 MB)
  1209→- All dictionaries that can grow unboundedly must have eviction strategies
  1210→
  1211→### Security
  1212→
  1213→- Never log API keys, Fernet keys, or tokens
  1214→- Always use atomic writes (`os.replace`) for persistent data
  1215→- Always encrypt tokens at rest with Fernet
  1216→- Validate DNS query structure before processing
  1217→- Never use `decode('utf-8', errors='replace')` for binary data
  1218→
  1219→### Testing Requirements
  1220→
  1221→- Unit tests for all new public methods
  1222→- Memory safety test for any new data structure that can grow
  1223→- Integration test for any new channel or router behavior
  1224→- E2E test for any new CLI command
  1225→
  1226→### Pull Request Checklist
  1227→
  1228→- [ ] All tests pass (`pytest`)
  1229→- [ ] Memory fix tests pass (`python scripts/test-memory-fixes.py`)
  1230→- [ ] E2E tests pass (`python scripts/test-e2e-pipeline.py`)
  1231→- [ ] No new unbounded data structures without eviction
  1232→- [ ] No API keys or secrets in logs
  1233→- [ ] Type hints on all new public signatures
  1234→- [ ] Docstrings on all new public classes and methods
